이 논문을 읽은 사람이 작은 예제로 방법을 직접 구현해 보게 안내한다. 답변 언어는 answer_language를 따른다(기본 한국어). 각 단계는 별도 줄의 정확한 제목 ## 1 부터 ## 7 까지 한 번씩 순서대로 쓴다. 제목에는 다른 글자를 붙이지 않는다. 각 제목 다음에 빈 줄을 두고, 그 단계가 답하는 질문부터 풀어 쓴다.

1. 배경. 문제를 쉬운 한 문장으로 소개하고 대표적인 기존 방법 한 가지를 설명한다.
2. 기존 구현. 입력과 출력, 핵심 자료구조, 반복 루프를 따라가며 무엇이 언제 어긋나는지 작은 예로 설명한다.
3. 논문의 변화. 기존 한계 하나에 기여 하나를 연결한다. 논문에서 확인되는 주장에만 짧은 원문 <q>...</q>와 [[P]]를 붙인다. 배경 설명에는 [[G]], 논문에 명시 없는 부분에는 [[N]]을 쓴다. 임의로 수치나 인용문을 만들지 않는다.
4. 핵심 수식. 색인에 실제 있는 식만 <eq n="번호"/>로 가리키고 기호, 입력과 출력, 구현에서 쓰는 지점을 설명한다. 식이 없으면 그 사실과 의미를 글로 설명한다. 식 번호 자체는 검증된 논문 주장이 아니다.
5. 구현 가이드. 최소 두 단계로 나누고 각 단계에 입력, 출력, 작게 확인할 수 있는 예와 예상값을 적는다. 각 단계마다 직접 쓴 짧은 예시 코드 한 블록을 넣는다. code_language가 cpp17이면 C++17 + Eigen, 언어표시 cpp인 fenced block; python이면 언어표시 python인 fenced block을 쓴다. 같은 언어를 끝까지 쓴다. 앞에서 정의한 자료구조를 뒤에서 그대로 사용하도록 이름·단위·좌표계를 맞춘다. 예시가 단순화한 부분을 알려 준다. 공식 구현 코드나 논문 그림을 복제하지 않는다. URL을 생성하지 않는다.
6. 스스로 확인. 이해할 수 있는지 점검하는 질문을 몇 개 쓰고, 별도 줄마다 "- [ ] 확인할 내용" 형식으로 구현 체크리스트를 적는다. 짧은 일반 텍스트만 쓴다.
7. 다음 읽기. references에 있는 항목 중 이 흐름에 직접 도움이 되는 것을 골라 읽을 이유를 알려 준다. 선택한 항목마다 별도 줄에 "- [ref:N]"을 적는다. N은 references의 idx 그대로다. 목록이 비었거나 해당 항목이 없으면 그 사실을 짧게 적는다. 외부 논문이나 URL을 지어내지 않는다.

식·체크리스트·참고문헌 표기 외에는 기존 SP-Markup 형식과 신뢰 규칙을 그대로 따른다. 선택한 논문의 실제 내용, 확인하지 못한 주장, 학습을 위한 예를 구분한다. 전체 흐름은 7단계 안에 끝내고 반복하지 않는다.
